# 试查：数字分身工作台首页 × 基础设计规范草案 v0.2

> 日期：2026-11-20。目的：拿一张常浩定稿、认可的页面，检验规范管不管用、数值准不准。**不是要改这张页面**：它是已定内容，下面查出的问题只报告，不动。
> 对象：数字分身 `docs/design/workbench.html` 的首页（2026-11-19 定稿，数据是示例）。
> 环境：Claude 桌面应用内置浏览器（Chromium），1440×900，本机静态服务打开定稿文件的副本；字体实际加载的是 JetBrains Mono（本机没装 Berkeley Mono，和定稿说明一致）。没有在 Safari 或真实应用窗口里看。
> 方法：脚本读取页面上 511 个可见元素的实际样式（字号、字重、颜色、间距、边框、圆角、位置），量对比度；再分三屏截图人工看。截图在 `~/Library/Application Support/ui-system/evidence/2026-11-20-audit-workbench-home/`。

## 一、结论

1. **构图和对齐类的规则，这张页面全部通过**，而且通过的原因正是你当初定稿时看中的东西。说明这几条规则抓的是对的。
2. **查出两处真问题**：36 处文字对比度不够；约三分之一的文字小于 12px。
3. **有四条规则写得不准或太严**，这张你认可的页面不符合它们，但页面并不难看。规范要改（见第四节）。

## 二、12 条红线逐条结果

| 红线 | 结果 | 证据 |
|---|---|---|
| A-01 落在对齐线上 | 通过 | 首屏主区的标题、导语、要点、表格共用 x=260 这条左边线；「等我拍板」6 行的五列位置逐行完全一致（277、389、913、1053、1153） |
| A-02 文字按基线对齐 | 规则写得不准 | 顶栏「首页」和日期基线只差 0.6px，通过。但清单行是把两行的主内容和单行的标签、按钮整体垂直居中，不是按首行基线对齐，看起来没问题 |
| A-03 刻意不对齐最多一处 | 通过 | 全页只有等距系统图是斜的，它正好是首屏的视觉重点 |
| S-01 间距只取自刻度 | **不符合** | 实际用了 30 多种间距，1 到 12px 几乎每个整数都有（3、5、7、9、11px 合计约 190 处） |
| S-02 亲疏分明 | 通过 | 区块标题上方 48–62px，离自己的内容更近（目测） |
| C-01 一屏一个重点 | 通过 | 首屏是大标题加系统图；第二屏是黑底的「等我拍板」 |
| C-02 默认不加容器 | 通过 | 整页带框的容器只有 8 个，最多嵌套 2 层。清单行、工作流行、自动化行都没有单独套框，只用细线分隔 |
| T-01 字号字重只取自层级表 | **不符合** | 首页用到 12 种字号（10、11、12、13、14、15、16、17、19、22、26、66px），4 种字重。整个文件的样式里还声明了 11.5、12.5、13.5、14.5px |
| T-02 对比度下限 | **不符合，36 处** | 见第三节 |
| K-01 颜色只引用角色 | 基本通过 | 28 个颜色变量，引用 522 次；页面里没有行内写死的色值 |
| K-02 有颜色必有含义 | 通过 | 橙色只给「我」和要注意的事，绿和琥珀只表示状态，和定稿说明一致 |
| D-01 交互状态写齐 | 部分 | 悬停有 12 条规则，键盘聚焦环有（2px 橙色），禁用态有；按下态没有 |

其他基础规则：边框粗细全页只有 1px（D-02 通过）；除了圆点没有任何圆角，形状一致（D-02 通过）；可点区域最小 32px 高（D-09 通过）；最长的一行文字 39 个字（C-07 通过）；字体族只有一种（T-01 这一半通过）。

## 三、查出的两处真问题

**1. 对比度不够，共 36 处**（页面上 289 段文字的 12%）

| 位置 | 实际对比度 | 要求 |
|---|---|---|
| 琥珀色小字，如「#221 卡在 GPT 审：网页未登录」（11px） | 2.42 | 4.5 |
| 琥珀色大数字「2」（26px） | 2.42 | 3 |
| 「CX」徽标（浅字配中灰底） | 2.81 | 4.5 |
| 橙色小字，如「默认」「等我拍板」「14:20」 | 3.27–3.48 | 4.5 |
| 橙底白字：数字「6」、档位「D」、「新建工作流」「规则改动」标签 | 3.83 | 4.5 |
| 侧栏里的灰色小字（20 处） | 4.43 | 4.5，只差 0.07 |

最该注意的是琥珀色小字：它写的正是「哪里卡住了」，却是全页最难读的字。

**2. 小于 12px 的文字占比高**

首页约 2100 个字符里，10px 的 145 个、11px 的 570 个，合计约 34%。多数是标签、编号、时间；也有整句话，比如上面那句 11px 的琥珀色提示，和侧栏底部的字体说明。

这两处要不要改，是改已定内容，由你决定。

## 四、规范要调整的地方（常浩 2026-11-20 回「按建议调」，已改进草案 v0.3）

| 规则 | 现在的写法 | 问题 | 建议改成 |
|---|---|---|---|
| A-02 | 同一行文字按首行基线对齐 | 清单行里「多行主内容 + 单行标签和按钮」整体垂直居中是常见做法，你认可的页面就这么做 | 只管并排的单行文字（标题和说明、标签和值）。一行里有多行内容时，居中或顶对齐选一种，全页一致 |
| A-01 的查法 | 只有一个元素用的对齐线算失误 | 会把边框造成的 1px 偏移、右对齐的元素误报 | 相差 1px 且由边框造成的算同一条线；右对齐和居中的元素按右边缘、中线算 |
| C-09 | 一屏文字不超过 4 级 | 这张页面每屏有 6–9 种字号，但眼睛看到的只有四档：大标题、区块标题、正文、标签 | 按「看得出的档」数，不按字号个数数。同一档里不要有两个相近的字号 |
| T-03 | 界面文字最小 12px | 你认可的页面有三分之一的字是 10–11px | 分两级：要读的句子不小于 12px；一眼扫过的标签、编号、时间不小于 10px。具体数值请你定 |
| S-01 | 红线：间距只取自刻度 | 这张页面没有刻度，但间距关系对，看起来就不乱 | 从红线降为基础要求。真正影响观感的是 S-02（亲疏关系），它留在红线 |
| 新增 | — | 橙色、琥珀色直接当小字用，对比度不够 | 加一条：彩色用作小字时用加深后的版本，色块上的文字颜色单独定（歸藏的做法） |

## 五、这次试查说明了什么

- 你最在意的四类失误里，「不对齐」和「笨重地堆」这两类，规范的规则在这张好页面上全部通过。还需要拿一张你否掉的差页面再查一次，看规则能不能把它拦下来。这一步没做。
- 脚本能量出来的项目（字号种类、间距种类、对比度、对齐线、嵌套层数）占了规则的一半左右，可以考虑加进 `ui-preflight`。
