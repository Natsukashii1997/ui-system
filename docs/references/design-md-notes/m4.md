# 模块 4 · 组件样式（Component Stylings）跨品牌归纳

- 材料：`modules/m4.md`，58 个品牌，3819 行，已完整读完。
- 口径：小节标题的家数是脚本按 `###` 标题数出来的（准确）；属性、状态的家数是「关键词统计 + 人工逐家核对」，带「约」的是有归类判断的。
- 标注：没有特别说明的都是「材料里写了」；我自己的判断一律标【推断】。
- 先说一个总前提：这 58 份是从各品牌**官网营销页**提炼的，所以组件几乎都是「落地页组件」（顶部导航、CTA 按钮、卡片、图片、信任条）。全材料里只有 Kimi 一家写了应用外壳、侧栏、输入区这类产品界面。对「中文、电脑版、交互产品」来说，这个模块能借的是**写法和属性清单**，组件范围要自己补。

## 3. 交互状态覆盖

### 3.1 各状态的家数和所在组件

| 状态 | 提到的家数 | 写在哪 |

| error | 3 家 | 输入框：IBM、Kimi、Cohere（猜测） |
| disabled | 2 家，各一处 | Kimi 发送按钮、Stripe 一个变体的用途 |
| loading | 0 家 | — |

补充（3.2 的几种手段有重叠，一家可能同时用两种，家数是「主要手段」的归类）：

- **同一个按钮上 hover + active + focus 三态写齐的只有约 6 家**：Apple、IBM、Notion、NVIDIA、Wise、Airbnb（圆形导航按钮）。再加 disabled 的四态：0 家。

- 多数家只给「主按钮」写状态，其余变体不写。例：Claude 5 个按钮只有 1 个有 hover；Kraken、Spotify 各 5 个变体，一个状态都没有。

### 3.3 焦点环怎么写

| 写法 | 约家数 | 代表 |
|---|---|---|
| `outline` 2px 实线 | 约 12 | Apple、Clay、Cohere、Coinbase、Ferrari、Lamborghini、Notion、NVIDIA、Vercel、Sanity（输入框）、Sentry（0.125rem）、Figma（2px **虚线**，呼应编辑器选框） |
| `box-shadow` 做环（2px 左右） | 约 7 | Airbnb（0 0 0 2px）、Revolut（0.125rem）、Uber（内环 2px 白）、IBM（2px 内环 + 1px 白色内圈）、Tesla（内阴影 2px，并预留 3px 透明边框）、Kimi（1px）、Wise |
| 只改边框颜色 | 约 8 | Claude、Zapier（变橙）、Framer、Stripe、IBM 输入框（底边 2px 蓝）、Raycast（边框提亮 + 蓝色光晕）、Cursor 输入框、Mintlify（1px 品牌色） |
| Tailwind 式半透明蓝环（蓝色 50%） | 约 4～5 | Lovable、Ollama、PostHog、xAI，ElevenLabs 类似 |
| 一层普通投影当焦点（`0 4px 12px` 10% 黑） | 4 | Cursor、Linear、Lovable、Supabase【推断：像是抓取计算样式的副产物，不是有意设计】 |
| 3px | 1 | HashiCorp |
| 只写「浏览器默认」 | 4 | Ferrari（输入框）、Renault、Tesla、Uber（输入框） |

- 颜色：蓝色约 16 家（Apple、IBM、Clay、Cohere、Claude、Framer、Vercel、Sanity、Raycast 等）；黑色约 6 家（Coinbase、Ferrari、Lamborghini、NVIDIA、Airbnb、Spotify）；品牌色约 5 家（Mintlify 绿、Stripe 紫、Zapier 橙、Sentry 紫、VoltAgent 薄荷绿）。
- 宽度：2px 是绝对主流（约 18 家），1px 约 5 家，3px 1 家。
- **偏移（outline-offset）：0 家明确写了数值**（「offset」5 处命中都是阴影偏移或 Tailwind 变量名）。
- 约 12 家出现了 CSS 变量名；其中 HashiCorp 的 hover、Pinterest 的 focus、Cal.com 的 focus、Cursor 和 Airbnb 的 hover 只有变量名、没有实际值，照着写不出来。

### 4.2 按钮内边距

- 最常见的一组是 **8px 16px**，9 家：Linear、Lovable、Notion、Sanity、Sentry、Spotify、Stripe、Vercel、Zapier。
- 其次 12px 16px（ClickHouse、Sentry、VoltAgent、Zapier）、8px 24px（Composio、Mintlify）、10px 12px（PostHog、Uber）、10px 24px（Ollama）、12px 24px（xAI）。
- 范围：纵向 8～14px，横向 12～24px 占绝大多数；胶囊按钮横向更大（Revolut 14 32、Supabase 8 32）。
- 约 13～15 家的内边距纵向是 0（如 Airbnb 0 24、ClickHouse 0 16、ElevenLabs 0 14、Expo 0 12、Intercom 0 14、Vercel 0 6），说明实际靠固定高度撑开，但**高度没写**，照着写不出同样大小的按钮。
- 给了高度的 4 家：IBM 48 / 40 / 64，Kimi 40 / 32（紧凑）/ 36（工具条），Tesla 40 / 32，Renault 46。【推断】电脑版产品常用 28～40px，这批材料的值偏大，因为是营销页 CTA。

| 4–8px | 23 | 其中明确「标准卡 8px」的 13 家：Cal.com、Claude、ClickHouse、Cursor、Expo、Figma、HashiCorp、Intercom、Linear、Together AI、Uber、Vercel、VoltAgent |
| 12–16px | 18 | 12px：Clay、Lovable、Notion、Ollama、Tesla；16px：Mintlify、Resend、Superhuman、MongoDB、Kimi、Wise |
| ≥20px | 4 | Airbnb 20、Cohere 22、MiniMax 20–24、Coinbase（8–40） |
| 没有卡片 | 3 | Kraken、OpenCode、SpaceX |
| 异常 | 1 | Replicate 写成胶囊 |

- 约 21 家给了「按大小分档」的圆角：标准 / 重点 / 大容器，如 Cal.com 8 / 12 / 16、Claude 8 / 16 / 32、Clay 12 / 24 / 40、Linear 8 / 12 / 22、MongoDB 16 / 24 / 48、Wise 16 / 30 / 40。
- 卡片内边距只有 6～7 家给数值，集中在 **16px 和 24px**（大卡 32px）。

### 4.4 输入框

- 圆角（约 28 家有值）：3–8px 18 家（4px：Clay、MongoDB、Notion、PostHog、Resend、Stripe；6px：Expo、Linear、Lovable、OpenCode、Sentry；8px：Cal.com、Miro、Raycast、Uber）；0px 2 家（IBM、xAI）；12–16px 3 家（Claude、Kimi、Pinterest）；胶囊 5 家（Mintlify、Ollama、Renault、Spotify、Airbnb 搜索框）。
- 内边距（约 20 家）：横向 12～16px 最多（Sanity 8 12、Sentry 8 12、IBM 0 16、Expo 0 12、Mintlify 0 12、Linear 12 14）；搜索框会为图标留很大的横向空间（Spotify 左 48、Linear 左右 32）。
- 高度：只有 IBM（40 默认 / 48 大）。
- 输入框圆角和按钮是否一致：一致约 12 家（Expo、Lovable、Linear、Stripe、Notion、IBM、xAI、HashiCorp、Clay、Mintlify、Ollama、Pinterest）；不一致约 8 家（Renault 按钮直角而输入框胶囊、Uber/Sanity/Resend/MongoDB 按钮胶囊而输入框 3～8px、Sentry 13 对 6、Claude 8 对 12）。

### 4.5 边框宽度

- **1px 几乎是唯一值**：51 家出现过 1px 边框。
- 例外：NVIDIA 主按钮 2px、Revolut 描边按钮 2px、VoltAgent 强调容器 3px 和高亮卡 2px、IBM 输入框底边 2px、Kimi 弹窗卡片 0.5px、OpenCode 标签页底线 2px、Zapier 标签页内阴影 4px。
- 约 10 家边框用半透明色而不是实色灰（Linear、Notion、Mintlify、Composio、Cursor、Raycast、Together AI、xAI、Kimi、Resend），好处是深浅底都能用。
- 约 11 家用「0 0 0 1px 阴影」代替边框（Cal.com、Vercel、Claude、Framer、Linear、Raycast、Resend、Wise 等）。

## 6. 写得好和写得差的差别

### 6.1 写得好的

**IBM**（58 家里最接近「照着就能写」）
- 主按钮一条里有：底色、字色、不对称内边距、圆角 0、**三档高度**（默认 48、紧凑 40、展示 64）、hover 色值、active 色值、focus（2px 蓝色内环 + 1px 白色内圈），并且每个色值后面带了设计令牌名。
- 变体按角色排：主、次、三级、幽灵、危险，后面的变体只写和主按钮不同的地方（「内边距、圆角同主按钮」）。
- 输入框写了别人都没写的东西：底色、高度两档、只有底边线、focus 和 error 各自的底边线颜色、标签字号和字距、辅助说明文字、占位符色。
- 卡片写了「靠底色分层，不靠阴影」和可点击卡片的 hover 底色、内边距 16px。

**Tesla / Ferrari / Lamborghini / Renault**（同一套模板）
- 每个变体固定三段：`Default` 一行把底色、字色、字号、字重、内边距、圆角、边框写齐；`Hover`、`Focus` 各一行；最后一行「用在哪」。
- Tesla 多写了最小高度 40px、宽度、为焦点动画预留的 3px 透明边框，以及过渡时长（全材料唯一）。Renault 给每个变体写了「深色背景上的反色版本」。
- 不足：没有按下、禁用。

**Kimi**（唯一写产品界面的）
- 有应用外壳（侧栏宽 240px、主面板边距和圆角）、侧栏导航项（宽 224、高 40、内边距、圆角、默认色和当前项色）、输入区（高度、边框、圆角、阴影、占位符字号行高、底部操作行高度）。
- 发送按钮写了禁用填充和可用填充两种状态；弹窗里的按钮单列「高 32px、内边距 0 10」；输入框写了 focus 和 error；图标给了尺寸（侧栏 20px、工具 16–18px）；还有一行空态面板。
- hover 的写法值得借：不写死颜色，写规则，意思是「填充色往上一级」。

**次一档**：Notion、NVIDIA 的主按钮（hover、active、focus、用途都有）；Mintlify 的卡片（底色、边框、圆角、内边距、阴影、hover 六项齐全）；Linear 每个变体都有用途一句话。

### 6.2 写得差的

**Airtable / Webflow / Miro**（整节只有 250～300 个字符）
- Airtable 的输入框只有一句「标准样式」；Miro 的主按钮写的是「从交互色推断是蓝色」。只有零散数值，没法据此写组件。

**Runway / BMW**
- Runway 按钮背景写「可能是透明或深色」；BMW 按钮没有底色和内边距，只写了字号和一段「行高 1.15～2.88，说明靠内边距撑开」的观察。是描述，不是规格。

**Composio / VoltAgent / Expo / Cal.com / Ollama**（共 8 家出现「likely」）
- 关键状态靠猜：hover「可能是降低透明度或略微变灰」；Composio 和 VoltAgent 的输入框整节是「没提取到数据，推断如下」。

**Kraken / Spotify / Claude**
- Kraken 5 个按钮变体、Spotify 5 个，全部只有静态属性，一个交互状态都没有。Claude 5 个按钮按颜色起名，只有 1 个写了 hover，圆角写成「8–12px」这种范围。

**数值照抄但没看懂**【推断：自动抓取计算样式的痕迹】
- Cursor 主按钮 hover 写成「文字变成错误色变量」；Lamborghini 的黑底按钮字色写成深灰（黑底深灰字不可读）；Figma 标题叫「胶囊」而圆角写 50% 圆形；MiniMax 名字叫「胶囊主按钮」而圆角是 8px；Notion、Vercel、Superhuman 按钮节写 4～8px，导航节又说 CTA 是胶囊。
- HashiCorp、Pinterest、Cal.com 的 hover/focus 只写了变量名，没有值。

### 6.3 差别归纳

| 好的写法 | 差的写法 |
|---|---|
| 一个变体一张属性单，属性固定、顺序固定 | 一段话描述，或属性时有时无 |
| 每个状态一行，给具体值 | 「略微变亮」「可能…」「见某变量」 |
| 变体按角色命名，写清「用在哪」 | 按颜色起名，不说什么时候用 |
| 给高度和尺寸档 | 只有内边距，纵向还是 0 |
| 后面的变体只写差异（「同主按钮」） | 每个变体重抄一遍，互相对不上 |
| 写规则（「填充色上移一级」「胶囊是直角规则的例外」） | 只有孤立数值 |
| 明确写「没有」（Apple：卡片无 hover；IBM：无阴影） | 不写，读的人不知道是没有还是漏了 |

## 7. 这个模块普遍缺什么（站在「中文、电脑版、交互产品」的角度）

前 9 条是材料里可以数出来的缺口，后面几条是【推断】。

1. **状态矩阵不全**：hover + active + focus 三态同在一个按钮上的只有约 6 家；disabled 2 处、loading 0、error 3 家；卡片、导航、标签页的 focus 是 0。次要变体基本不写状态。
2. **没有尺寸档位**：按钮高度只有 4 家写，分档的只有 IBM（Kimi、Tesla 各有两个高度）。输入框高度 1 家。没有一家写「小号用在工具栏、默认用在表单」。
3. **没有密度**：表格 1 家、列表 0 家；行高、单元格内边距、紧凑/宽松两档都没有。全文没有出现过「density」。
4. **缺整类组件**：弹窗、下拉菜单、气泡、工具提示、toast、复选/单选/开关、下拉选择、分页、面包屑、树、滚动条、头像，基本都是 0～2 家。
5. **没有空态、加载态、错误态**：空态只有 Kimi 一行；骨架屏、加载圈 0。
6. **没有「什么时候用哪个」**：约 31 家按钮有用途一句话，但都是举例（如「用于『立即开始』」），没有选择规则（一屏最多几个主按钮、次按钮和幽灵按钮怎么选），也没有禁用场景。组件小节里出现的「不要」基本为 0（留给了模块 7）。
7. **弹层没有规格**：宽度、圆角、内边距、遮罩色、阴影、层级顺序、关闭方式都没有；全文没有出现过「z-index」。
8. **选中/当前项不成体系**：约 15～18 家各有一句，没有一家把「默认、hover、选中、选中后 hover、禁用」放在一起写。
9. **没有文字溢出和宽度规则**：最小宽度、最大宽度、截断省略号的命中都是 0；图标按钮有形状没有尺寸，图标尺寸只有 Kimi 写了。
10. **动效时长**：只有 Tesla 写了过渡时间，其余 hover 效果都没有时长和缓动。
11. **深浅色两套**：约 38 家提到深色表面上的变体，但多是「再列一个深色按钮」，只有 Kimi、Renault、Claude 的部分条目是「同一组件两套值」的写法。
12. 【推断】**键盘操作**：除了焦点环，没有 Tab 顺序、回车和 Esc 的行为、快捷键提示；只有 Linear 提了一句命令面板触发键、Raycast 写了键帽样式。电脑版交互产品需要。
13. 【推断】**中文适配**：13 家靠「大写 + 字距」做按钮和标签的层级（ElevenLabs、Sentry、xAI、NVIDIA、SpaceX 等），中文用不上，需要换成字重、字号、颜色来区分；按钮内边距都是按英文单词调的，中文 2～4 个字的按钮需要自己定最小宽度；字号 10～11px 的徽标（Stripe、Linear、Lamborghini）中文不可读，【推断】中文建议不低于 12px。
14. 【推断】**多余的部分**：约 29 家在导航里写手机端汉堡菜单、39 家有图片处理、28 家有营销特色组件。只做电脑版的交互产品可以整段不要。
15. 【推断】**浮窗类产品特有的缺口**：窗口外壳（标题栏、拖动区、关闭按钮、窗口圆角和阴影、最小尺寸）没有任何一家涉及。

## 8. 写组件样式的模板

### 8.1 整个模块的结构

```
4. 组件样式
  4.0 通用规则（所有组件共用，只写一次）
  4.1 … 4.N 各组件（每个组件用同一套小节）
```

**4.0 通用规则**应该一次回答完的问题（各家把这些散落在每个组件里，所以对不上）：

| 问题 | 写成什么样 |
|---|---|
| 尺寸档 | 例：小 28 / 默认 32 / 大 40（高度），每档对应的字号、横向内边距、图标尺寸；哪一档用在哪（工具栏、表单、弹窗底部） |
| 圆角档 | 例：控件 6、卡片/面板 8、弹层 12、胶囊 999 只给标签和筛选 |
| 边线 | 宽度（1px）、颜色令牌、什么时候用边线、什么时候用底色或阴影 |
| 状态规则 | hover、按下、选中各自怎么变（例：底色上移一级 / 下移一级）；禁用统一怎么处理（透明度多少、鼠标指针）；加载时怎么显示 |
| 焦点环 | 宽度、颜色、偏移、用 outline 还是阴影；只在键盘聚焦时显示 |
| 动效 | 状态切换时长和缓动（例：120ms） |
| 图标 | 尺寸（16 / 20）、与文字间距 |
| 文字溢出 | 单行截断还是换行；最小宽度、最大宽度 |
| 深浅色 | 所有值写令牌名，不写死色值 |

### 8.2 每个组件固定写这 6 个小节

1. **用途与不用的场景**：一句话定义；什么时候用它、什么时候改用别的组件；数量限制（如一个区域最多一个主按钮）。
2. **结构**：由哪几部分组成（图标、文字、后缀、关闭按钮），顺序和间距。
3. **属性表**（默认态）：一行一个属性，固定这些列：

   | 属性 | 值（写令牌） |
   |---|---|
   | 高度 / 最小宽度 | |
   | 内边距 | |
   | 圆角 | |
   | 背景 | |
   | 文字（字号、字重、颜色） | |
   | 边框 | |
   | 阴影 | |
   | 图标（尺寸、间距） | |

4. **变体**：按**角色**命名（主、次、幽灵、危险），每个变体只写和默认不同的属性，再加一句「用在哪」。
5. **状态矩阵**：行是变体，列是状态，格子里写「变什么」。没有的状态写「无」，不要留空。

   | 变体 | 默认 | hover | 按下 | 键盘焦点 | 选中 | 禁用 | 加载 | 错误 |
   |---|---|---|---|---|---|---|---|---|
   | 主 | | | | | 无 | | | 无 |
   | 次 | | | | | | | | 无 |

6. **尺寸档与密度**：小/默认/大各自的高度、字号、内边距；列表和表格另写紧凑/默认两档行高。

可选的第 7 节：**内容规则**（文案长度、中文按钮 2～4 字、溢出怎么办、空态文案）。

### 8.3 各组件还要额外回答的问题

| 组件 | 额外要写的 |
|---|---|
| 按钮 | 图标按钮的尺寸（正方形边长）；带图标时的内边距；按钮组的间距和主次顺序；加载时是否保持宽度 |
| 输入框 | 标签位置、必填标记、占位符色、辅助说明和错误提示的字号与位置、前后缀图标、只读态、清除按钮 |
| 选择类控件 | 复选/单选/开关的尺寸、勾选色、半选态；下拉选择的触发器样式和选项样式 |
| 列表项/表格 | 行高（两档密度）、单元格内边距、表头样式、分隔方式（线/隔行底色/无）、hover 行、选中行、数字列对齐、列宽和截断、空表和加载中 |
