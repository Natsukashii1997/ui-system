## 1. 每家写多少条

| | 范围 | 中位数 | 最常见 | 分布 |
|---|---|---|---|---|

## 5. 规则的写法质量

### 比例（脚本粗分 + 人工抽样，属估计）

把每条规则在破折号前的「规则本体」拿出来看：

| 类型 | 条数 | 占比 | 说明 |
|---|---|---|---|
| 带数值或色值 | 383 | 约 47% | 有明确对象 + 数字，直接可判定 |
| 不带数值，但对象明确、非此即彼 | 约 330 | 约 41% | 如「任何元素不加阴影」「不用衬线体」。其中大半可判定，小半要靠理解（如「不引入暖色」） |
| 靠形容词，没有阈值 | 约 97 | 约 12% | 「重」「克制」「装饰性」「繁忙」「大面积」 |

- 我的估计：可直接判定的约 65–75%，明显空泛的约 12–20%，其余在两者之间。
- Do 比 Don't 具体得多：Do 里含数字的约 67%，Don't 里只有约 38%。原因是 Don't 常常只写「不要重阴影」，把数值留在 Do 里。
- 约 69% 的条目（556/810）带理由从句。但理由绝大多数是「这是品牌标志」「是故意的」「不可商量」这一类（「signature」出现在 19 家，「intentional」20 家，「identity」17 家）。能指向可读性、可见性、可访问性这类功能性原因的，人工估计约 30 条，占 4% 左右。

### 可判定的例子（转述）

1. HashiCorp：阴影不透明度不得高于 0.1。
2. Composio：内容卡片圆角不得大于 4px。
3. Sanity：圆角不得取 13px 到 99998px 之间的值，只有 12px 以内和全圆两档。
4. Renault：所有按钮的最小可点击尺寸为 46×46px。
5. Tesla：每屏最多 2 个操作按钮；网页上文字不超过 40px。
6. Clay：同一区块里最多混用 2 种色板色。

### 空泛的例子（转述）

1. Miro、Cohere：不要用重阴影（没说多重算重）。
2. Ferrari、Lamborghini：不要做出有多个焦点互相竞争的繁忙布局。
3. Runway：不要和视觉内容抢戏。
4. PostHog：不要让设计显得「精致」「高级」。
5. Revolut：不要用小按钮。
6. Superhuman：不要大量使用阴影。

### 写得最好的几条长什么样

- ClickHouse：黑底上不用柔和阴影，因为看不见；改用边框做层次。（对象 + 原因 + 替代做法）
- Linear：主文字不用纯白，用 `#f7f8f8`，避免刺眼。（对象 + 替代值 + 功能原因）
- Cal.com：展示字体 24px 以下要加 +0.2px 字距，否则小字号会挤。（条件 + 数值 + 功能原因）
- ClickHouse：强调色不做背景填充，主按钮除外。（带例外）
- VoltAgent：暖色只用于警告、错误这类状态，不做装饰。（把「例外」写成明确范围）

### 一条好护栏的格式（推断，从上面归纳）

```
[对象：哪个组件的哪个属性] + [约束：数值、上下限或可选档位] + [适用范围和例外]
→ 原因（写功能性后果，不写「这是我们的风格」）
→ 替代做法（不许这样，那该怎样）
```

判断一条规则合不合格的三个问题：
1. 换一个人或一个 AI 来查，能不能只回答「是 / 否」？
2. 违反了能不能指到具体哪一处、差多少？
3. 被禁之后，他知不知道该改成什么？

## 6. 普遍缺什么（中文、电脑版、交互产品的角度）

以下「缺」都是对着 53 家材料数出来的；「对用户意味着什么」是推断。

| 缺口 | 材料里的情况 | 对用户意味着什么（推断） |
|---|---|---|
| 没有严重程度分级 | 53 家全是平铺的列表。「不可商量」这类词出现在约 7 家的个别条目里，只是修辞，不是分级 | 16 条规则同等重要，等于没有重点。需要分「红线 / 默认 / 建议」 |
| 原因多是「风格如此」 | 带理由的 556 条里，功能性理由约 30 条 | 遇到规则没覆盖的新情况，无法从原因推出该怎么办 |
| 没有检查方法 | 0 家写怎么查 | 规则没法进代码检查或验收清单 |
| 没有例外条款 | 只有零星几条带「除了……」（ClickHouse、VoltAgent、Apple） | 实际做的时候例外最多，没写就各自发挥 |
| Do 和 Don't 大量互为镜像 | 如 Airbnb 的文字色、强调色各写两遍。粗看每家约三到五成的 Don't 只是 Do 的反面（估计） | 16 条里的有效信息可能只有 10 条左右 |
| 交互状态几乎空白 | 悬停约 17 家；焦点约 5 家；禁用、加载中、空状态、报错、键盘操作 0 家 | 交互产品最容易出错的地方完全没管 |
| 文案为零 | 没有措辞、语气、标点、数字格式的规则 | 中文界面的按钮文字、提示语、报错话术要自己从头定 |
| 排印规则多数不适用中文 | 负字距（约 20 家要求）、大写加宽字距（约 22 家）、OpenType 字形集（13 家）、510/460/320 这类非标准字重（Linear、Superhuman、Figma）都只对拉丁字体成立。提到中文字体的只有 Kimi（PingFang） | 约三成排印护栏不能搬。中文要另写：中英混排、字重只有固定几档、不压字距、标点处理 |
| 可访问性没有数 | 提到对比度的只有 Sanity，且没给比值；可点击尺寸只有 Renault 给了数 | 对比度、最小点击区域、焦点可见性要自己补数值 |
| 偏营销页 | 大量规则围绕首屏大标题、区块间距、主按钮、摄影 | 工作台和浮窗要管的是信息密度、表格、表单、面板、列表，这些没人写。只有 Kimi（保留 240px 侧栏、不要用小组件塞满主面板）和 Uber（保持紧凑）沾边 |
| 没有暗色模式护栏 | 暗色品牌只写了自己的暗色；没有「明暗两套如何对应」的规则 | 如果要做明暗两套，需要单独一节 |
| 没有窗口相关规则 | 0 家提到最小窗口、浮窗、置顶、拖拽、滚动条 | 电脑版独有，需要自己加 |

## 7. 写设计护栏的模板（推断，给用户用）

### 分类与建议条数

总量建议 30–40 条，其中「红线」不超过 10–12 条。依据：材料里每家 16 条左右，只覆盖视觉；加上交互、文案、窗口三块后翻一倍是合理上限，再多就没人记得住。

| 类别 | 建议条数 | 要回答的问题 | 材料里可借的写法 |
|---|---|---|---|
| A 色彩 | 5–6 | 强调色有几个、各用在哪、最大面积多少；能不能新增颜色、谁批准；纯黑纯白用不用；状态色（成功、警告、错误）能不能挪作他用；灰阶的色温 | 「强调色只给主操作和交互，不做装饰」约 19 家；「状态色不做装饰」Renault、Ferrari |
| B 中文排印 | 5–6 | 字号有哪几档、最小几号；字重用哪几档、最粗到哪；行高范围；中英混排和数字用什么字体；字距动不动；什么时候截断、什么时候换行 | 「字重只用三档」Vercel；「正文行高不低于 1.40」Claude |
| C 圆角、边框、阴影 | 4–5 | 圆角有哪几档、各对应什么组件、中间值禁不禁；层级靠边框、阴影还是底色，选哪一种为主；阴影上限；边框粗细上限 | 「只有两档，中间值禁用」Ollama、Sanity；「不透明度不超过 0.1」Vercel 等 |
| D 布局与密度 | 4–5 | 间距基数（如 4 或 8 的倍数）；行高、控件高度有哪几档；一个面板里主操作最多几个；内容最大宽度 | 「间距都是 8 的倍数」IBM；「每屏最多 2 个操作按钮」Tesla；「不要用小组件塞满主面板」Kimi |
| E 交互状态与动效 | 5–6 | 每个可交互元素必须有哪几种状态（默认、悬停、按下、焦点、禁用、加载）；悬停只许改哪些属性；动效时长上限和缓动；什么情况必须有加载、空、报错三种状态 | 「悬停只变色，不缩放位移」Tesla；「过渡统一 0.33s」Tesla；Cursor 的 150ms/200ms 分档 |
| F 文案 | 4–5 | 按钮用动词还是名词、最多几个字；报错话术的结构（发生了什么 + 怎么办）；标点、数字、单位、中英文之间空格；禁用词 | 材料里没有，全部要自己写 |
| G 键盘与可访问性 | 3–4 | 文字对比度最低多少；焦点框长什么样、不许去掉；最小可点击尺寸；哪些操作必须有快捷键 | 「焦点框 3px 实线」HashiCorp；「最小 46×46px」Renault（这是触屏值，电脑版要另定） |
| H 窗口与浮窗 | 3–4 | 最小窗口尺寸；浮窗的尺寸档位、能不能遮挡主操作；滚动条和溢出怎么处理 | 材料里没有；和模块 8 的改写版合并考虑 |

### 每条规则的格式

```
编号｜级别｜对象｜规则｜例外｜原因｜替代做法｜怎么查
```

- 级别三档：
  - 红线：任何情况不许违反，违反必须改；
  - 默认：照做，要破例先说明理由；
  - 建议：没有特别理由就照做。
- 规则：必须带数值、上下限或可选档位，能回答「是 / 否」。
- 原因：写后果（看不清、点不中、和状态色混淆），不写「这是我们的风格」。风格类规则的原因写「定过，见某处」。
- 怎么查：能搜代码的写搜什么（如搜写死的色值、搜 `font-weight: 700`）；不能搜的写「看哪张截图、比什么」。

示例（数值是占位，不是建议值）：

```
C-02｜红线｜所有组件的圆角｜只许 0 / 6 / 12 / 全圆 四档，其他值禁用
｜例外：头像和图片容器跟随内容
｜原因：档位之外的值会让同屏元素看起来不是一套
｜替代：拿不准用 6
｜怎么查：搜 border-radius，值不在四档内即违规
```

### 写的顺序（推断）

1. 先写「档位」：颜色有哪些、字号哪几档、圆角哪几档、间距哪几档。这属于模块 2–6，但护栏依赖它。
2. 再写护栏：每条都是「不许越出某个档位」或「某档位只许用在某处」。
3. 最后对每条问第 5 节的三个问题，答不上来的重写或删掉。
4. Do 和 Don't 不要各写一遍。一条规则只写一次，用「只许……；不许……」合在一起。

51 家有分档表，档数 2–9：

|---|---|---|---|---|---|---|---|---|
| 家数 | 2 | 6 | 9 | 10 | 9 | 10 | 2 | 3 |

### 大屏最大内容宽度

- 材料里这一节很少给具体数。给了的只有：
  - Kimi：营销页最大宽 1280px；应用里输入框居中、最大约 768px；侧栏 240px。

  - OpenCode：内容区居中，约 800–900px。

- 大标题从桌面到手机通常缩到 50–60%（64 → 36、56 → 32、72 → 32）。

## 10. 只做电脑版时，这一节怎么处理

### 哪些还有用，哪些可以整段不要

| 仍然有用（改个说法保留） | 可以整段不要 |
|---|---|
| 分档表的格式：「名称 / 宽度 / 主要变化」三列。改成窗口宽度档位表，只列 1280、1440 和更宽的一两档 | 768px 以下的所有断点，以及 640、768、1024 这几档 |
| 声明最小支持宽度（约 7 家写了）。改成「最小窗口尺寸，低于它横向滚动」 | 导航变汉堡菜单（约 45 家） |
| 最大内容宽度与超宽屏居中（约 33 家提到）。要写明超过基准宽度后多出来的空间给谁 | 网格 3 → 2 → 1 列的折叠（约 45 家） |
| 侧栏规则（Kimi、Spotify、Cursor）。要写宽度、能不能收起、什么时候自动收起 | 大标题字号随宽度递减（约 40 家） |
| 正文字号不随窗口变化（NVIDIA 写了「正文在所有断点保持 15–16px」） | 区块间距随宽度缩小（约 28 家） |
| 代码块、表格、数据图在容器内横向滚动，不换行不压缩（约 10 家） | 触控目标 44px、「方便拇指」、手机上按钮通栏（约 11 家） |
| 组件高度档位（IBM 的 48 / 40px，Kimi 的 36–46px）。改成鼠标指针的最小点击尺寸 | 页脚折叠成手风琴、底部标签栏、分类标签横向滑动 |
| 图片和截图保持宽高比、圆角不变（约 27 家） | 手机上换构图、裁切更紧、隐藏二维码等内容 |
| 输入区或阅读区单独设最大宽度（Kimi 的输入框约 768px，OpenCode 的内容区约 800–900px） | 懒加载（属于性能，不属于设计规范） |
| 弹窗宽度相对窗口的写法（Kimi：窗口宽减 32px） | 轮播、滑动手势 |

### 改写模板：「窗口与尺寸」一节（推断）

下面 8 条是我根据材料里仍有用的部分，加上用户的约束（基准 1440×900，1280 宽仍完整，再窄横向滚动，不做手机版）推出来的。材料里没有任何一家这样写过。方括号里是要用户自己填的值。

1. **支持范围**：设计基准 1440×900；1280 宽时所有功能完整可用；窄于 1280 出横向滚动，不重排布局；不做手机版和触屏适配。
2. **窗口档位表**：只列三档，每档写「主要变化」。
   | 档位 | 宽度 | 主要变化 |
   |---|---|---|
   | 最小 | 1280 | [哪一栏收窄到最小宽度；哪些次要信息收起] |
   | 基准 | 1440 | 按设计稿 |
   | 宽屏 | [1680 或 1920] 以上 | [多出的宽度给哪一栏；内容区是否封顶居中] |
3. **谁固定、谁伸缩**：逐个区域写固定宽度还是弹性宽度，以及最小和最大值。例如侧栏固定 [240]，主区弹性且最小 [数值]，右侧面板固定 [数值]。1280 到 1440 之间的差值由哪一栏吸收，要写明。
4. **内容最大宽度**：阅读类内容的最大行宽 [数值或每行字数]；输入区最大宽度 [数值]；表格和看板是否铺满。超过后居中还是靠左。
5. **侧栏和面板的收起规则**：能否手动收起；收起后的宽度；是否在某个宽度自动收起；状态是否记住。
6. **不随窗口变化的东西**：字号、行高、间距、控件高度一律固定，不跟窗口宽度缩放。（依据：NVIDIA 的「正文不变」。和营销页的做法相反，应用里连标题也不该缩。）
7. **溢出规则**：长文本什么时候截断加省略号、什么时候换行；表格的列最小宽度、超出后容器内横向滚动；代码块不换行、横向滚动；高度不够时哪一块滚动、哪一块固定。
8. **指针目标与浮窗尺寸**：鼠标点击的最小尺寸 [数值，电脑版通常比触屏的 44px 小，具体值材料里没有依据，需要自己定]；浮窗的固定尺寸档位、最小和最大尺寸、能否拖动改变大小；窗口高度低于 900 时浮窗怎么处理。

还可以考虑但没放进 8 条的（推断）：浏览器缩放到 90%–125% 时是否仍完整；高分屏下细线和图标的处理。这两项材料里没有任何依据。
