## 0. 一句话结论

它和 58 份 DESIGN.md 不是一类东西。58 份是别人从官网反推出来的色值和字号清单；这份是 Vercel 自己写给 AI 的工作说明，**色值和字号一个都没写**（全部放在样式表里），正文写的是：先想清楚读者要什么，怎么选构图，什么时候才配用一个框，交付前怎么自查。

所以它对「与风格无关的基础规范」帮助最大：它的大部分规则换一种风格仍然成立。

它管的范围要记住：**给客户看的报告类网页**（报告、提案、对比、计算器），明说不是产品界面。产品界面特有的东西（表单流程、导航、空态、权限）它没有覆盖。

## 1. 它的结构

| 部分 | 写了什么 | 值得学的写法 |
|---|---|---|
| 定位 | 谁写的、给谁看、要什么气质（准确、平静、克制、以证据服人） | 用「不靠什么建立信心」来定气质，比形容词好判 |
| 优先级 | 要求互相冲突时保谁：事实和约束 → 调用方的工程 → 读者的问题和答案 → 品牌识别 → 针对这份材料的构图 → 细节打磨 | 规则有先后，AI 不用自己猜 |
| 何时问人 | 只在会改变商业含义、法律安全、公式单位、对象身份这类事上问，一次问完；其余的标注未知、继续做 | 把「该问的」写成封闭清单 |
| 四遍工作法 | 弄清读者的任务 → 选构图 → 按视觉系统做 → 自己看、自己改 | 流程和规则写在一起 |
| 视觉系统 | 外壳、网格与对齐、文字与节奏、颜色与边界、数据与表格、计算器、动效、图片图标 | 每节都是「什么时候才能用」，不是「长什么样」 |
| 自查顺序 | 第一眼 → 文字 → 构图 → 字体 → 证据 → 克制 → 主题与换行 → 可信与无障碍 | 固定顺序，每项一个问题 |
| 拒绝清单 | 17 种一眼看得出是 AI 生成的默认做法 | 写成能逐项对照的清单 |
| 样式表接口 | 只许用列出的类名和令牌，不许自己造、不许读实现 | 令牌是唯一来源 |

## 2. 提炼出的规则，和基础规范的对应

规范编号见 [基础设计规范](../design-spec/DESIGN.md)（写本文时是 v0.3）。

### 对齐

| 它怎么说 | 规范里的 |
|---|---|
| 每个元素都要对到共用的边、基线、网格线，或一个有意的视觉中心 | A-01 |
| 并排的标题和段落按第一行基线对齐；页眉里的标志和说明同一条基线 | A-02 |
| 同级的块，文字角色、数值位置、内部行、操作的位置都一样；不因为某一项字多、数大就单独调 | A-04 |
| 数字列和它的表头都右对齐；同级的单位和精度一致，不加假精度；对齐的数字用等宽数字 | A-05 |

### 间距

| 它怎么说 | 规范里的 |
|---|---|
| 间距表达关系：标题贴近它的第一段；内容组到新的一节明显更大；说明贴近它说明的东西。组内、组间、节间各用一段刻度 | S-02 |
| 每个间距只有一个负责的元素，子元素不带自己的外边距；不用一次性的外边距修某一处 | S-03 |
| 留白要衬托重点。分栏没填满、第三项落单、证据来得太晚造成的大块空白是版面失误，要重排 | S-04 |

### 构图

| 它怎么说 | 规范里的 |
|---|---|
| 每个阅读时刻一个重点，周围配少量辅助内容。眯眼看重点要一眼可见；把字模糊掉层级还在；每块一样重就重做 | C-01、第 11 节自查 1、2 |
| 页面默认是一整块连续的底。只有表达选中、可操作、警示、对比、或间距表达不了的真分组，才配用框和底色 | C-02 |
| 不给每一节、每个指标都套卡片；不嵌套面板 | C-03 |
| 重复只有在各项是真正同级时才成节奏，否则是模板噪音；不让不相关的内容用同一个版式轮廓 | C-04 |
| 滚动要有节奏，密和松交替 | C-06 |
| 说明文字每行 60–68 个字符；表格、图表这类证据占满整个宽度，不把宽表挤进窄栏 | C-07 |
| 层级先靠文字建立，再考虑表面和颜色 | C-08 |
| 逐个看表面、边框、胶囊、图标、标签、颜色、段落，删掉不损失含义和操作的就删 | C-11 |

### 文字、颜色、细节、质感、动效

| 它怎么说 | 规范里的 |
|---|---|
| 只用已发布的字号角色和字重，不造任意字号 | T-01 |
| 检查重要的断行；大标题里落单的字靠改文案或改行宽解决，不靠缩小 | T-06 |
| 颜色只取公开的令牌，不自造、不改名 | K-01 |
| 先按黑白灰设计。颜色只在表示状态、操作或数据时用，不因为「这是好消息」就标绿 | K-02 |
| 颜色要配一个不靠颜色的提示 | K-03 |
| 浅色和深色两套都要有同等的层级和对比度 | K-05 |
| 控件有可见的标签、聚焦状态；键盘和读屏都能用；达到 WCAG AA | D-01、T-02 |
| 图标不做装饰，不放进彩色方块；风格不混用 | D-04 |
| 不用库存图、假截图、装饰性的 AI 插图 | Q-02 |
| 用边框去补救弱层级算失误 | Q-04 |
| 17 条拒绝清单：装饰渐变和光晕、居中大标题接卡片网格、重复的指标方块、到处用胶囊、图标方块、卡片套卡片等 | Q-06 |
| 默认静止。动效只用来说明状态变化、保持连续、确认操作；不靠动画才能读完；尊重「减少动态效果」 | M-01、M-02 |

## 3. 规范里还没收、以后可以收的

这些换风格也成立，但基础规范（v0.3、v0.4）没有对应的条目。要不要收由常浩定。

1. **数据图表的诚实**：长度类的图从零开始；同一组条形共用一把尺，轨道起止在同一条线上，只有填充长度变；直接标注优先于图例；分母不同时先说清比的是数量还是比率。规范现在没有「图表」一节。
2. **表格的细则**：五列以上的表占满整宽；不为同一个类别重复占一列，改用分组；先按读者的查找任务排列顺序，再考虑缩窄；长表默认只显示和决策有关的子集，并写明筛选规则和总数。
3. **一个结论只有一个主场**：同一个答案不在摘要、图、卡片、结论里用同样的分量重复出现。
4. **两种阅读速度**：只看标题、关键数字和说明能读懂结论；表格、假设、方法、出处留给要核对的人。
5. **分开判断「多」和「吵」**：觉得乱，是内容太多，就删、合、重排；觉得吵，是手段太强，就减颜色、字号、字重、边框。
6. **规则优先级和何时问人**：规范的附录 A 第 9 项只留了位置，没有给写法，可以照它的两段来写。
7. **选构图前先点名「这类页面最顺手的版式」，没有理由就不用**；材料有多种排法时，先比两种真正不同的构图。

## 4. 不要照搬的部分

| 它的做法 | 为什么是风格、不是底层 |
|---|---|
| 只用 Geist 字体、黑白灰为主、圆角克制 | Vercel 的品牌选择 |
| 禁用全大写小标题、装饰性的节编号、破折号 | 文案和版式风格。常浩风格库里的细线风格就用带编号的小标题 |
| 禁用网格背景、条纹、纹理 | 细线风格的页首就是网格背景 |
| 不放可见的明暗切换 | 报告页的选择，产品界面常常需要 |
| 表格正文一律按第一行基线对齐，不许垂直居中 | 和基础规范有意不同：试查数字分身工作台首页后，A-02 改成多行的行可以整体居中，全页同类的行用同一种（见[试查报告](../design-spec/audits/2026-11-20-数字分身工作台首页.md)） |
| `vbg-*` 类名和令牌、页眉页脚的标志外壳 | 它自己的实现，学的是「令牌只有一个来源，不许自造」这个做法 |

## 5. 和另外两份参考的关系

- [歸藏设计规范提炼](2026-11-20-歸藏设计规范提炼.md)：歸藏强在把规则写成数值和脚本，管内容排版；Vercel 强在构图和克制的判断标准，管报告页。两家都禁装饰、都要求令牌唯一来源；在纯黑纯白、网格背景上相反，这些就是风格。
